# 轮回修仙幸存者 · R12 网页原型

按 R12 三份文档（设计案、系统设计案、内容库）做的浏览器可玩原型。每年做一个决定，劫难里把这一世带进战斗，死后回到轮回井，带着天书、命灯和宿慧开始下一世。

> 这是一套新写的代码，**不是**本地 `F:\AiProject\LHXX\web` 那份工程。技术栈和画风参照它：Canvas2D 战斗视图，淡蓝水墨风。为了好跑，这里没用 Phaser，只用了 Vite + TypeScript + 原生 Canvas。

## 运行

```bash
npm install
npm run dev        # 本地开发，浏览器打开终端里提示的地址
npm run build      # 类型检查 + 打包到 dist/（相对路径，可直接放静态托管，例如 GitHub Pages）
npm run sim -- 40 all 1   # 无界面批量模拟：[世数] [safe|chance|war|all] [种子]
npm run make-save -- 20 chance 1   # 用真实引擎跑出一份多世存档，写到 public/saves/twenty-lives.json
```

存档放在浏览器 localStorage 里（`lhxx.web.meta.v3` / `lhxx.web.life.v3`），每年岁末自动存一次，刷新页面后可以继续这一世。重置在「设置」里。

顶栏「存档」（`src/game/saves.ts`）：三个手动档位（`lhxx.web.slot.1..3`，整份拷贝当前进度）、读档前自动备份（`lhxx.web.slot.backup`）、导出 / 导入 `.json` 文件，以及预置的「二十世存档」（`public/saves/twenty-lives.json`，由 `npm run make-save` 生成）。第一次打开带存档系统的版本会问一次要不要载入二十世存档，已有进度会先进自动备份。

## 操作

- 人生层（命途棋盘）：先点棋盘下方的「掷骰」（或空格 / 回车）摇出一颗骰，再点骰子（或按 1）走到它指的格；不满意就点「再摇一次」（或按 R）。再摇次数属于本世，开局 1 次，事件、天机格骰签、入宗门能多拿，死后清零。勾上「自动摇」只是自动揭开点数，不会替你再摇。走完一格，结果先在棋子那格冒一个小提示，详情仍在上方画卷左上角；也可以先点格子看说明，再点一次发光的格子走过去。`窥命` 消耗每圈的改命次数（点地点格）；`如意骰` 任选点数；`回溯` 需要掌天瓶，只能在一圈开头用；`自动` 按设置里的倾向替你掷骰、打理产业和天机格（遇到引子、故人、遗迹、劫气积聚的岁首或血量低于 30% 时会停下）。窄屏默认收起棋盘，可直接掷骰；点「展开棋盘」查看地块，窥命时会自动展开。手机上的大棋盘可横向滑动；键盘可用 Tab 选中地块，再按回车查看或前往。
- 劫难：`WASD` / 方向键移动，功法自动出手；`1` `2` `3` 用主动法宝（手机是右下的圆钮），`Q` 收剑，`P` 暂停。战斗里没有升级三选一了，打完会显示各功法出力。
- 行囊：顶栏「行囊」、角色栏「功法」旁的「行囊」，或出征、闭关、坊市弹窗里的「打开行囊」。卷轴式界面：左边是打坐的自己，身边四个功法位、两个随身位，脚下三个符丹位，下面是属性与当前加成；右边按「全部 / 法宝 / 随身 / 符丹 / 附诀」翻页查看。点任意一格看详情，在详情里换法宝、装备或取下、挂上或取下附诀、选引雷目标；新得的东西会自动填进空位。
- 手机：竖屏优先。顶部状态条点开是角色详情；劫难里按住屏幕任意处拖动即可移动，右上角暂停，右下角收剑。可以「添加到主屏幕」当 App 用。

## 已知缺口

- 场景卡的主体是按关键词猜的（276 个带选项的事件里人物 104、奇遇 56、战斗 52、交易 30、修炼 15、采集 5，另有 14 个只画地点），个别事件会归错类；行动卡图标也是按动作名的关键词配的，配不上的用动作名第一个字盖印。渡劫、奇遇、死亡这些关键事件还没有专属画面。

- 修炼与法宝相对现行文档的简化：被动 / 主动法宝没有品级；器灵统一为伤害 +8%；天阶「绝技」统一为圆满后伤害 ×1.25；功法残页只来自奇遇事件和坊市（30% 概率上架）；灵器以上的法宝只记入遗泽，还没有变成遗迹秘库的专属奖励；身份的专属开局只做了数值（灵石、属性、道途、宗门功法、法器），宗门产业开局还没落地；A02「凡俗奇遇 +10%」只记成就、效果未做；A10、A25 的奖励文档没写明，暂定宗门 +2、顶级 +1。战斗的整体倍率 `BATTLE_POWER` = 1.1 是按模拟胜率对齐改版前定的。

- 命途棋盘是按 `npm run sim` 初调的：改成一颗骰加再摇后，每世约 50–60 圈、每圈停 3.4 格，遭遇战稳健约 5 场、求缘约 7 场、好战约 7 场（劫气积聚改为连续 8 圈未战才起、一战即散），自动模式每世用掉约 10–13 次再摇；每世要掷约 200 次骰，比去向卡时（约 90 次）多，「自动摇」能省掉一半的点击，真人试玩后可能要再缩短一圈的停格数。佛子「受具足戒」目前只给修炼 ×1.1，内容库里的「破戒代价翻倍」还没做。
- 一人千面里有几处是近似实现：心魔难度体现为镜像血量，妖潮减伤借用布阵效果，「改命 +2」在下一年生效，「道心」条件换成了悟性/气运；Y10 的奖励给功德与灵感，不推进心愿；海国年没有海妖专属画面。
- 事件库扩充的简化：不少链内标记和世内标记只记了文字、还没有机制（如 wineKept、tomb、secretOut、gateGuest、trueEndLead、library_ban 等），斩仙葫芦、酒葫芦、储物戒、补画针等收获也只有描述；YG04 签到碑的连签只按「5 圈没去就断」计，3/7/12 次的里程碑做成了拍；YG36「香火成神」的结拍在生前（40 岁后）而不是死后；D01、D02、YG23 的时机条件是近似的；C-病榻-4 的司灯台词是占位。几处拍子加了年龄或入道的门槛（如求亲要 16 岁、白头到老要 40 岁、宗门遭劫要入道），等门槛期间这条链会一直占着一个链位。事件给的寿元每世有上限（60 + 本境寿元的 30%），防止卡境界时靠重复奇遇无限延寿。
- 因果链按 `npm run sim` 初调（3 个种子 × 120 世）：每世开约 5 条链，走完的里约 1/3 上档；约一半断链，多数是自动模式没去「缘」格，真人会更主动；约 6 成的世有灵宠、近 4 成有道侣；抉择与上一世重复的比例从约 29% 降到约 6%。`npx tsx scripts/check-content.ts` 检查链和奇遇数据的引用。
- 经历图谱的「因」连线偏少（每世约 0.5–0.8 条）：它只认事件出现条件和选项条件里读到的世内标记，而现有事件大多只看年龄、境界、地点，很少看前面发生过什么；要让图谱更密，得在内容里多写「因为做过 A，才会遇到 B」的条件。一世最多记 400 件事，超出时先丢没有连线的流水小事；跨世只存 8 世，更早的世里的牵连显示为「已散佚」，轮回数据最多约 200～240 KB。
- 「玩家就是打碎天门的人」这一反转还没定，相关内容没有做。
- 命途分岔的比例按随机选择的模拟调的（入道的世约两成走到修为尽头，其中约一半等到转机），真人会更多地避开歧路，需要试玩再调。
- 数值是按文档目标初调的，靠 `npm run sim` 看指标，还没经过真人试玩。
- 美术是程序绘制的（风格见下），还没有手绘素材和背景音乐。

## 美术与表现：「青冥画卷」

世界是一幅画：云海之上的青绿仙境，石柱仙峰、瀑布、白金仙宫、白衣御剑的青光，墨潮是这幅明亮画面里唯一的纯黑。全部用 Canvas / CSS 程序绘制，不依赖外部素材。

- 画卷舞台（`src/art/scene.ts`）：卷轴上方的横画，按年代换天色、按境界换青绿浓淡、按地点换点景（22 个地点）、按年纪换小人，劫气重时墨从画底漫上来，死后转到轮回井。
- 命途棋盘（`src/art/board.ts`）：45° 俯视的菱形立体地块，按前后深度遮挡；22 个地点有各自的微缩场景，本命、产业、后果、歧路与遗迹也有对应图形。劫、凶、缘、引、故用不同图形和印签提示，白衣棋子沿地块逐格移动，目标地块发光。桌面上经历与棋盘左右分栏，各自滚动；窄屏默认收起棋盘，为事件正文留出阅读空间，展开状态下正文仍独立保留。
- 关键时刻演出（`src/art/moments.ts`）：入世展卷、测灵根、入道、破境、劫难开场、身死、得天书，点按可跳过。
- 音效（`src/art/sound.ts`）：WebAudio 现场合成的古琴、磬、鼓、锣，设置里可关。
- 字体：马善政毛笔楷书（标题、大字）与霞鹜文楷（正文），均为 SIL OFL，按游戏用字裁剪在 `src/art/fonts/`；文案改动后跑 `python3 scripts/subset-fonts.py <MaShanZheng.ttf> <LXGWWenKai.ttf>` 重新裁剪。

## 目录

```
src/data/      文档内容（天赋、境界、天书、心愿、词条、地点、抉择、同伴事件；faces.ts 是一人千面，fate.ts 是命途分岔，chains-*.ts 是因果链，encounters-*.ts 是扩充奇遇）
src/game/      人生引擎、存档、随机数（chains.ts 是因果链与新收获）
src/battle/    战斗规则（sim.ts，可无界面运行）与 Canvas 视图（view.ts）
src/main.ts    界面
src/art/       美术表现：配色、画卷舞台、演出、音效、字体
scripts/       批量模拟脚本
```
